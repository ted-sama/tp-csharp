2. Avec Where(n => n is not null) on garde un IEnumerable<Note?> : le compilateur pense

1. Delegues et lambdas

1.1
3. La variable est de type Func<Note, bool>. On ne peut pas ecrire var c = n => n.Valeur >= 15;
   le compilateur dit CS8917 "Impossible de deduire le type delegue" : il ne sait pas ce
   qu'est n, donc il ne peut pas deviner le type de la lambda.

1.3
- On obtient 10 puis 6. La lambda ne copie pas seuil, elle garde la variable elle-meme,
  donc au 2e appel elle voit seuil = 15.
- En Java ca ne compile pas : une variable utilisee dans une lambda doit etre
  "effectively final", et ici seuil est modifiee.
- Pour garder 12, on copie la valeur dans une autre variable qu'on ne touche plus
  (seuilFixe), ou on passe le seuil en parametre comme avec AuDessusDe(12).

4. L'evaluation differee

1. On obtient 6, puis 7, puis 8 / 7.
   - 6 : il y a 6 notes >= 15.
   - 7 : bonnes n'est pas un resultat, c'est la requete. Elle est relancee au Count() et
     voit la note de 19 ajoutee entre temps.
   - 8 / 7 : bonnes voit aussi la 2e note ajoutee (20), alors que figees a ete calcule
     avec ToList() avant l'ajout et reste a 7.
2. Avec deux Count(), chaque note est testee 2 fois (26 tests pour 13 notes). Avec ToList()
   d'abord, chaque note n'est testee qu'une fois (13 tests).
3. Count() > 0 teste les 13 notes. Any() s'arrete a la premiere qui correspond, ici la
   toute premiere (Ada, Algo, 15), donc 1 seul test.
4. Le resultat est le meme. Avec le Where avant, seules les 6 notes gardees passent dans
   le tri. Avec le Where apres, les 13 notes sont triees. Mieux vaut filtrer avant.


5. Reecrire la classe Promo

1. Si l'etudiant n'a aucune note, Sum / Sum fait 0 / 0 et on obtient NaN (pas d'exception
   parce que c'est un double). Pour l'eviter on verifie d'abord s'il y a des notes et on
   renvoie 0 sinon.
2. Releve : 1. Grace 16,67 Tres bien / 2. Ada 15,17 Bien / 3. Barbara 13,67 Assez bien /
   4. Linus 12,25 Assez bien / 5. Alan 10,33 Passable.
3. C'est beaucoup plus court qu'a la seance 1 : la plupart des methodes tiennent en une
   ligne au lieu d'une boucle de 6-8 lignes. C'est plus lisible une fois qu'on connait
   les operateurs, on lit directement ce qu'on veut (filtrer, grouper, trier). Et c'est
   plus facile a modifier, par exemple changer le critere de tri c'est juste changer
   une lambda.
4. Oui, Classement() refait tout le calcul a chaque appel. Ici ce n'est pas un probleme,
   il n'y a que 13 notes. Il faudrait le mettre en cache (ToList une fois) si les donnees
   etaient tres grosses ou si on l'appelait souvent, par exemple dans une boucle.
